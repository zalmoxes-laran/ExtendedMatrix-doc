# Gemini Image Generation Prompt — Extended Matrix Knowledge Tree

## Style Reference
Use a clean, modern scientific illustration style with the Extended Matrix visual identity:
- Color palette: deep teal (#2C3E50), warm orange (#ED8936), forest green (#48BB78), royal purple (#6B46C1), earth brown (#8B6914)
- Clean lines, subtle gradients, no heavy textures
- Professional but approachable, suitable for academic publication
- White or very light cream background
- San-serif typography (similar to Segoe UI or Helvetica)

---

## Prompt

Create a conceptual illustration of the "Extended Matrix Knowledge Tree" for archaeological data management. The image should represent a stylized, elegant tree viewed from the front, with these elements:

**THE TRUNK (center, prominent)**
- A strong, clean trunk representing the GraphML file
- Label it "GraphML" with subtitle "Stratigraphic Sequence"
- The trunk should feel solid and essential — it's the necessary foundation
- Color: warm wood tones (browns/amber)
- On the trunk surface, show small symbolic icons: connected nodes, arrows pointing up/down (representing stratigraphic relationships like "overlies", "cuts", "fills")

**THE MAIN BRANCHES (growing from trunk)**
- 3-4 major branches growing upward and outward from the trunk
- Each branch represents a core graph component:
  - Left branch: "Relationships" (overlies, cuts, fills, abuts, bonds)
  - Center-up branch: "Chronology" (periods, phases, epochs)
  - Right branch: "Paradata" (extractors, documents, provenance)
  - Optional: "Node Types" (US, USV, SF, USD...)
- Branches should be in rich green tones
- They are part of the tree structure itself (inseparable from the trunk)

**THE LEAVES (abundant, on branches)**
- Many individual leaves on the branches, each representing a granular data property
- Each leaf is a small tag/label with a property name:
  - "Material", "Technique", "Measures", "Color", "Definition", "Interpretation", "Conservation", "Components", "Notes", "Source PDF", "Site", "Area"
- Leaves should be in lighter green tones, distinct from branches
- Some leaves could look like small Excel/table icons to emphasize their tabular origin
- Leaves are numerous and give the tree its richness and fullness

**THE ROOTS (below ground)**
- Subtle roots visible below the ground line
- Representing the sources: "PDF Reports", "Field Notes", "Photos", "Databases"
- A few roots could be labeled with source types
- Color: lighter brown, slightly transparent

**ANNOTATIONS / CALLOUTS**
- Small annotation box near the trunk: "Managed by project leader · yEd / EMtools · Changes infrequently"
- Small annotation box near the leaves: "Updated by working group · Excel / Databases · Continuous updates"
- An arrow from roots to trunk labeled "AI Extraction / Manual"
- An arrow from external table icon to leaves labeled "Auxiliary Import (on-the-fly)"

**OVERALL COMPOSITION**
- The tree should be centered, taking up about 70% of the image
- Below the tree, a simple ground line separating roots from trunk
- The image should convey the message: "The graph is the backbone, the tables are the living detail"
- Keep it clean enough for academic slides and documentation
- Aspect ratio: 16:9 or 4:3, landscape orientation
- Resolution suitable for web documentation (at least 1200px wide)

**MOOD**
- Scientific but warm
- The tree should feel alive and growing — the knowledge system is organic and evolving
- Not a diagram with boxes and arrows, but a real tree metaphor rendered artistically
- Think: "a tree of knowledge in an archaeological context"

**TEXT TO INCLUDE**
- Title at top: "The Extended Matrix Knowledge Tree"
- Subtitle: "GraphML as trunk · Core properties as branches · Auxiliary data as leaves"
- Footer: "Extended Matrix v1.5 — extendedmatrix.org"
